# 内部图片库维护与使用（c17）

点状显示选择“外部图片”后，“图片来源”仍有固定、字段分类映射、字段值、外部字段绑定四种模式。固定和每条映射可分别选择来源形式 URL／图片库。

图片库弹窗按文件名搜索，忽略大小写，多关键词以空格分隔且需同时匹配。确认只写入图片引用；宽高、锚点、局部偏移及 Halo 在外部设置，全局基础点回退仍独立。取消或 Esc 不修改选择。

## 文件维护

- 上传到 Web 仓库 `public/image-library/`，保持平铺目录。支持 PNG、JPG/JPEG、WebP、GIF、AVIF。
- 上传／修改后提交并部署 Web，刷新页面即可检出，不需要改索引文件、图片清单、契约或 SCF。
- 文件名是搜索名称，也是稳定引用的一部分。允许中文与空格，生成地址时自动编码；文件名须忽略大小写后唯一。
- 原有文件改名或删除可能破坏历史引用。缺失时工作台保留来源标记及原地址，显示具体提示；实际加载失败使用原有全局回退。
- 同名替换在部署后刷新生效；图片库使用独立可重新校验的缓存策略，页面运行中的内存资源不主动重新下载。
- 首批为卫星地图公开标记素材：43 个世界／图标文件去重后 25 张。`TR100px.png.png` 是原始实际文件名，不是上传错误。

## 配置与迁移

固定图片的 `image` 示例（省略其他已有参数）：

```json
{"mode":"fixed","sourceForm":"library","url":"/image-library/N1.png"}
```

映射行独立保存 `sourceForm` 与 `url`。`sourceForm:"url"` 即使填写同样的图库路径，重新打开仍是 URL；`sourceForm:"library"` 即使文件已删除，仍是图片库。两个动态字段模式不携带这个字段。

旧 c16 配置继续按原契约读取和运行。通过顶部明确迁移入口，或导入旧包的既有候选转换流程，逐级到 c17；旧固定／映射图片一律补 URL 来源形式，不猜测路径。核验通过后按原流程发布，配置修订仍由服务端分配 rN。

配置 ZIP、分类／Class 树和临时诊断包携带引用及呈现参数，不附带图片二进制；另一套 Web 部署须同步对应目录。共享核验只验证来源标记及路径格式，不远程检查目录。

## 维护入口

`scripts/image-library-plugin.mjs` 自动扫描并检查文件头、零字节及名称冲突；不会自动去重后续上传的文件。虚拟目录列表只进入按需加载的选图模块，不生成手工维护的 JSON。

修改契约时继续遵守 [契约更新要求](ContractUpdates.md)。相关回归为 `npm run test:c17` 和 `scripts/config-tools/browser/image_library_acceptance.py`；浏览器实操进入 PR CI，不进入生产 build。
