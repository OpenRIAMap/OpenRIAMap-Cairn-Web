# 契约、逐级迁移与兼容更新要求

此文档与 `src/configStudio/README.md` 是配置契约更新的核心说明。配置修订 r 与契约 c 分开：`revision: 11, contractRevision: 14` 显示为“配置 r11 · 契约 c14”。历史 r13 契约与更名后的 c13 是同一份结构，历史文件和散列不重写。

## 支持范围与迁移目标

`contract.ts` 是能力来源。读取、启用、分类归档、工作流归档和正式发布分别声明范围。c15 实现支持历史正式 c11／c12／c13／c14，并新增 c15；不能将“历史可编辑”理解成所有旧契约都可直接正式发布。

新自动迁移链从 c13 起，最低源版本是 `max(13, target - 5)`。例如 c15 接受 c13～c15；c18 接受 c13～c18；c19 接受 c14～c19。源码保留历史转换器，超窗时不自动调用它们伪装成窗口内来源。

组件导入到当前工作稿契约，不自动升级总包。完整包导入对窗口内来源使用 Web 最新可写契约，并在入口显示目标；结果是待核验候选。c12 及以前使用明确的完整包历史迁移，再重新导出组件。恢复本机检查点保留来源契约和未完成编辑，只有明确升级才改变契约。

## 相邻版本步骤

每次契约升级要提交相邻步骤、支持种类及测试。每个步骤只将上一版本的完整结构转换为下一版本完整结构。整包由同一批组件转换器和全局规则转换器组成，需核对跨组件依赖；不能复制一套与组件导入不同的转换。

新增必填项用安全默认，新可选项省略并报告待补充；必填业务关系没有安全默认时保留错误，不能猜目标 ID／URL。只删除明确废弃的属性，不以“目标 schema 中没有这个键”为由删除用户字段。保留继承和部分覆盖，不将可省略的覆盖写成关闭而截断继承。

迁移器不得修改输入、发起网络请求、依赖当前时间或不稳定 ID，也不自行累计配置修订号。缺步骤、未知契约、反向或结构损坏时停止，保留原件和当前基线。同版转换保持等价。

## c14 Halo（历史行为）

Halo 使用 `{enabled, widthPx, color}`；完整基础点、每个 Icon、每个图片 presentation 保存独立设置，线／面主样式保存 `RenderStyle.halo`。默认关闭、粗细 2 CSS px、白色。粗细范围为 0～72；颜色复用五种模式。图标／图片失败时使用独立回退点 Halo。

线和面沿同一路径以 `原宽度 + 2 × Halo` 绘制底层；透明面允许看到内侧外环。图标有底板时沿底板，无底板时沿图案轮廓；外部图片按配置宽高矩形外缘，不读透明像素。图标扩大的是画布，原图大小和锚点通过 padding 补偿保持原位。

配置字段、编辑器、默认值、预览、依赖遍历、核验、正式地图、碰撞边界和交互清理必须一起实现。折叠属于编辑器偏好，不改变契约数据。

## 必须交付的证据

每次升级提供相邻迁移夹具、源文件摘要未变、全部分类／树／工作流往返、整包与组件等价、支持窗口及防降级测试。浏览器必须实际执行导入、报告、区域保存、顶部核验、导出再导入、恢复未保存草稿及所有新增控件；截图与测试结论分别记录。

版本文案审计要区分当前身份、最低能力、历史协议和测试夹具。共享 Node 核验器应由 Web 同源生成，Pipeline 按随包能力清单识别契约，保留历史规则标识。不得只改一个最新版本数字后宣称完成适配。

真实登录、SCF、COS 和生产发布另作部署后验收；本机模拟不能当成正式发布成功。完整回归放 PR CI，生产 build 不在线请求 SCF，也不重复完整回归。

## c15 相邻转换及维护要点

c14 → c15 覆盖整包、分类、Class 树和工作流；整包与组件使用同一转换。圆形记录旧实际半径；面添加 showInner；几何级锚点和触发移至每条规则并删除旧权威位置；单路径输出转为分类组。保留原 outputId、组装、槽位、顺序、返回绑定和实际编辑路由优先级。旧的无效 rule.interaction 不因升级突然启用。

工作流片段缺少分类树上下文、来源路径已失效时停止并保留原件。转换不猜测末端和父节点，不读取网络；新 selector ID 从旧 outputId 稳定生成。未变化的引擎、对照表、导航及共享铁路角色原样保留。

c15 的部分条件样式沿用没有覆盖的主规则属性。面内侧开关必为布尔值，只允许出现在面几何 Halo；完全和部分覆盖均按最终有效设置绘制。新建和类型切换时补齐目标 Halo 默认值，不能在有效规则中遗漏必需属性。

c15 精确记录分类与结构末端分开：合法父节点可通过数据核验；仅有目录用途且未启用相应几何的节点仍不能存储记录。普通数据资格不依赖某条工作流是否存在；运行某条工作流时额外检查其候选成员资格。核验和输入资格均使用共享解析器，不重复实现叶节点判断。

工作流输出必须逐候选核对字段及条件组装。跨输出依赖保留原 outputId 和数组索引，不能为了逐候选核验截断工作流。共同字段只用于编辑建议，动态结果仍在实际提交时按所选节点严格核验。更改分类树、selector 或固定类型后，旧选择不得静默替换为第一项。

共享 Node 核验器及 Pipeline 保留 c14 的历史 rulesVersion；部署新核验器不要求重新发布配置，也不更改已有激活时间。只有新配置契约正式发布后才显示为 c15。

## c15 修复版本：分类直选与逐候选写入

分类组结构和 contractRevision 仍为 15。工作台使用四级范围选择，实际填写保留一个类型下拉框；选项显示末级代号（名称）而内部保存完整分类路径。精确父级与混合深度都可直选，不能扩大为层级浏览器。

字段集合的交集仅用于提示。组装、预填同时绑定、绘制返回、回填必须按实际来源对每个可达候选检查字段、值数量、格式、结构及必填供值。合法的不同字段定义可以接受同一实际值；未使用的普通可选字段差异不阻断。

共享核验规则身份升级为 `cairnmap-c15-production-2`，内容指纹变化使本地旧核验记录重新检查。旧 `cairnmap-c15-production-1` 任务上下文仍可读取，但不能拿旧凭据跳过新实际值检查。未完成的配置发布应在部署前处理完毕；已确认发布凭据不得静默升级授权。
