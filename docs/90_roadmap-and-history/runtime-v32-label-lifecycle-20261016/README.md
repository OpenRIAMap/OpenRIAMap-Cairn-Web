# 缩小时旧标签残留：修复与全分类核验（2026-10-16）

基线为 Post-C v1.1 交付提交 `51d9e432b9086a151bf1ce4a224ff2b0e0d2d211`，工作树开始时干净。本次仅本地修复和提交，不推送、不同步上下游。默认配置仍为 r11/r7，配置 JSON、ZIP 和 V1 原始显示规则均未修改。

## 原因和修复

RLE 已有逻辑 Zoom 0–1 的规则 `v1-rle-dir3-geometry--base`，其 `label.visible=false`，只保留线几何；不是缺少低 Zoom 默认条件。2–4、direction=3 的小线路标定义也符合已批准的设计。

问题在共用渲染生命周期：

1. 标签仍携带 declutter 设置时，单个几何的更新函数把标签维护留给统一布局阶段。
2. 新规则关闭标签后，统一布局仅进入 `enabled && declutter` 分支，缺少关闭分支的清理。线几何仍可见，最终“整个要素隐藏”的清理也不会执行。于是旧 Marker 及其点击层仍挂在地图上，却没有新布局请求，无法继续参与候选、碰撞和密度计算。
3. 摆放缓存和拖动时刷新标记原先也只在请求列表非空时维护；最后一个请求消失时会留下旧状态。

现在关闭标签时显式卸载该要素的旧标签及所有部件标签，并在每轮刷新中统一清理不再存在的摆放缓存；请求为空时也重置实时布局标记。重新进入显示区间后重新执行有效请求的候选、碰撞和密度计算，合法的几何显示继续保留。

此前的线路标浏览器验收主要按 0→8 检查，漏掉了从显示区间退出的反向缩放。这次保留修复前复现，并补充永久的反向、冷／热状态对照和实际动画回归。

## 其他分类排查

以冻结 V1 运行规则为参照，对默认包全部 95 个分类、7 组 direction／Level／Connect 输入、Zoom 0–8 共 5,985 组标签适用条件进行比较。除已批准的 RLE direction=3、Zoom 2–4 增量外，没有发现新的标签开关阈值偏差；不需要为其他分类补造低 Zoom 规则。

以下 12 类存在缩小时退出标签显示的分支，共用清理修复同时覆盖它们。不同子分类和字段取值的边界可能不同：
