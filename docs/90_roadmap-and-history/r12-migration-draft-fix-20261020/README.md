# r12 迁移草稿操作与恢复修复

日期：2026-10-20。基于 Web 主分支 `6e3e8f5`。

点击“迁移到 r12 草稿”后，分类选择被清空且禁用，顶部全局核验因未保存草稿而禁用。原有草稿核验、保存、放弃入口位于引擎设置和分类管理之后，未出现在首屏，使迁移流程看起来没有出口。无法在整包迁移草稿中切换分类也妨碍逐项检查。

现在整包草稿在设计标签下方始终显示“核验整包草稿／保存整包草稿／放弃整包草稿”。核验通过后才能保存，保存仍需确认且仅应用于本机；正式上传继续要求已保存配置的全局核验和维护者身份确认。

整包迁移、隔离导入和无选中分类的全局编辑保留整包范围，可以切换分类检查。普通分类编辑与 Class 树编辑保持原有事务边界。范围只存入浏览器编辑会话，不进入配置 JSON 或 ZIP。旧版尚未保存范围的迁移会话根据契约变化和分类选择自动识别，更新 Web 后刷新即可恢复操作，不必清除缓存。

## 部署和继续操作

本次仅更新 Web。合并修复 PR 并等待生产部署完成后，刷新工作台，既有迁移草稿会恢复并显示顶部操作栏。根据需要核验保存，或放弃本次迁移后重新导入配置。本次没有改动共享核验器、SCF 包、环境变量或正式配置，无须重新部署 SCF。

工作台顶部显示的是**当前本地编辑配置**，迁移按钮基于这一份配置建立草稿；线上正式身份由发布流程另外检查。本次随 Web 注册的正式 r9 与默认 r7 已逐字段比较，只有 `/revision` 不同，功能内容一致，因此截图中的 r7 可以继续本次迁移，无须为此清缓存或强制重新导入。未来若本地编辑内容与正式基线不同，应导入最新正式基线或由它生成的候选再迁移；“恢复应用默认配置”并不表示获取最新正式配置。

后续状态机调整及完整使用流程见 [包级候选编辑与全局引擎独立保存](../studio-package-and-engine-20261020/README.md)：整包候选不再锁定在要素设计标签，三个区域分别核验保存，候选最终统一提交。
