## DATA-01：默认共享、允许特定世界群独立绑定完整来源组（用户新增要求）

### 配置模型与编辑方式

- 默认仍采用全应用共享的数据链路、瓦片来源和世界路径模板；未显式另选的世界使用默认组，不要求每个世界重复配置。
- 允许在“数据仓库与来源”新增完整的“世界群来源配置组”。每组具有稳定 ID、名称 zh/en，并集中定义自己的数据链路与来源策略、数据／媒体根地址、世界路径模板及 TILE-01 的瓦片配置，供一组指定世界使用。来源组不是 REUSE 体系的值对照表，不改变已经冻结的公共表范围。
- 世界列表增加可选的“来源配置组”引用，默认显示“使用全局默认组”；单个世界也可以单独组成一组。“适用世界”若在组面板编辑，须修改同一引用关系，不额外维护相互竞争的成员清单。每个世界同时只解析到一个有效组。
- 不恢复逐世界分别填写仓库、读取器、瓦片根地址的零散覆盖。原 `dataSourceId` 不作为独立优先级保留，而是明确迁移到完整配置组引用；世界只选组，并保留世界本身的身份、名称、编号及必要的远端世界键。
- 新建组、调整适用世界、切换默认组及删除／重命名组均提供影响报告；跨来源／世界定义的关联变更作为一次候选配置核验并原子保存，不能先保存悬空世界引用再要求另一模块补齐。被引用组删除须先明确重新分配，默认组必须有效且唯一。

### 统一解析、切源和身份隔离

- `getRuleDataSourceSnapshot(worldId)` 等入口改为先解析世界所属来源组，再采用该组的显式选源结果。保留标准化解析流程，不沿用“仅全局默认源被选中时才使用世界覆盖”的隐式优先级分支。
- 每组具有自己的来源选择／发布快照状态；显式应用、失败重试及备用访问方式限定在该组。默认组切源只影响使用默认组的世界，独立组切源只影响该组世界，不能失败后偷偷读取另一服务器的数据。
- 同一组内保持一致的来源／发布快照，禁止自动混用不同发布版本；不同服务器组可以拥有各自的合法发布版本，不强求所有服务器 release ID 相同。来源修改、世界重绑和旧请求取消均以组和应用配置版本为边界。
- 当前应用世界 ID 及既有需要全局唯一的前缀／编号继续校验；不同服务器可以有相同的远端世界名，例如各有 `world`。模板使用显式配置的远端世界键，默认继承当前世界 ID；读取器明确映射远端 World 与应用世界，不靠同名猜测归属。
- 数据、图片、瓦片、搜索索引、临时挂载、要素定位及关系解析的内部身份包含来源组／应用世界上下文；两个服务器具有相同远端世界名或要素 ID 时不能相互覆盖。不得为了缓存去重擅自修改仓库中的要素 ID、既有记录或原有输出组装规则。
- 主图、搜索、导航、信息卡、测绘／再编辑、测量和 Config Lab／验证器均使用同一个已解析上下文。来源群绑定只新增本项的数据／瓦片归属，不自动复制审核认证或玩家后端接口；依赖这些接口的操作若无法确认目标归属，应明确阻断而非误送默认服务器。
- 每组使用已注册、经过校验的标准读取协议与访问方式。当前代码仅接入 `formal-release-v2`，新增配置不等于自动支持任意服务器的数据格式；未知协议须报告未支持，不能仅填 URL 就绕过适配校验。

### 默认保持与历史迁移

- 当前默认包各世界都引用 `formal-cos`，按现有实际参数迁移为同一默认组，不默认添加无用途的其他服务器组，原有显示和数据选择结果保持。
- 旧自定义包若存在不同世界来源或瓦片设置，按完整来源／模板组合识别并生成对应组和世界引用；参数不一致不能仅因数据源 ID 相同就强行合并。无法归一的路径／旧参数保留并报告，不静默丢弃或挑选一个替代。
- 契约、schema、默认包迁移、独立模块保存、整包导入导出及历史恢复同时支持来源组及世界引用；配置组缺失／禁用、世界重复归属、无有效默认组和不支持的读取协议均可定位阻断。

## TILE-01：组内共享瓦片来源与世界路径模板（配合 DATA-01 修订）

- 已核实当前默认原版入口 `https://satellite.ria.red/map/_{world}/tiles/world/` 与手绘／水彩入口 `/api/dynmap/_{world}/tiles/world/` 实际指向同一 Satellite 原图。Vite 代理及 Vercel rewrite 将后者转发到前者；手绘／水彩在浏览器 Canvas 上生成滤镜效果，没有单独的风格图片仓库。
- 默认组保留当前瓦片来源；新增来源组可以定义另一套瓦片根地址、世界路径模板、图层名、图片格式、额外缩放及原生边界、署名和重试参数。每组集中设置，组内世界仅代入自己的远端世界键；世界列表不重复展开整套瓦片参数。
- 数据链路和瓦片配置归属同一个完整组，世界切换或重绑时一起解析并应用，不能展示服务器 A 的底图却误叠服务器 B 的数据。发布替换／加载失败时须明确加载或错误状态，不保留另一组要素伪装成已完成切换。
- 每组的直连与同源代理仍是同一原图的访问方式；界面不把代理入口描述成另一套“手绘／水彩数据源”。原版、手绘、水彩必须取自所选组的同一原图，仅滤镜渲染不同。
- 当前 Vercel rewrite 的目标固定。支持新增服务器组必须落实该组实际可用的直连／CORS 或已部署代理映射；代理路由按已注册来源组识别目标，不能把任意目标 URL 交给通用转发接口。前端保存地址不等于部署已支持，未接通的代理应明确报告，不能仍转发到默认服务器后宣称切源成功。
- `prefix=flat` 是瓦片图层／地图名，界面“简称”仍改为含义明确的“瓦片图层名”。同名图层可属于不同组，模板解析必须保留组上下文。
- 继续使用全应用共享逻辑 Zoom 0–8 控制显示区间，瓦片组的额外缩放及原生上下限控制取图层级；全部采用 ZOOM-01／PROJECTION-01 的共享映射／投影机制，不因新增来源组再暴露原始矩阵或另设一套逻辑 Zoom。
- 原版 `DynmapTileLayer` 与手绘／水彩 Canvas 图层统一取图、重试和错误处理。共享实现接受有效组参数，不能只改编辑框或让滤镜图层仍硬编码默认地址。
- 修复原版 `createTile` 错误回调捕获初始 `retryCount`、只重设 `tile.src` 未推进计数的问题；测试 0／1／3 次上限、成功清理、瓦片卸载。切换世界／来源组、改组配置及取消旧请求后，迟到回调不能写回当前瓦片或继续无限重试。
- 缓存、请求去重和已加载资源按组 ID、配置／发布版本、应用世界及实际瓦片参数区分；组内更新只使相关资源失效，避免全图无关刷新，也避免仅按 `{world}/{z}/{x}/{y}` 命中另一服务器瓦片。
- 署名继续用结构化名称与链接保存，显示当前生效组的署名，保留旧合法内容的迁移处理。

- 副本状态在模块中显示完整可编辑对照表：名称 zh、名称 en、存储值及添加／删除／排序；使用现有 grip 规则。移除仅有“本地显示对照 n 项；需要更新时重新预填”的摘要式呈现。
- 保留明确的清除入口，清除本地对照不删除控件、输出组装行或信息卡显示字段。独立副本不会因来源修改而自动改变；来源变化可保留可定位的更新提示与“确认保留副本”，不能伪装成实时绑定。
- 更新提示的审计可记录字段／表格快照来源，但不能参与运行取值；多次增量预填后须更新对应证据，清除或解除后不得遗留错误的来源约束。本地行编辑沿用当前表格，不另设一套“手动覆写”开关或重复编辑区。
- 本轮明确细化旧预填审计：副本的来源删除本身不作为实时依赖失效阻断；只要副本自身及目标配置合法，就可以独立保存。实际引用缺失仍按 REUSE-05 阻断。

## REUSE-03：“绑定”直接引用字段对照或公共表

- 下拉选项与信息卡对照旁均提供与“预填”并列且可区分的“绑定”。可选择指定分类字段的对照，或公共表格；字段设计的对照区继续支持绑定公共表。
- 下拉选项绑定只控制选项对照和存储值类型，不把工作流的控件名称、必填、提示、默认值、执行条件等全部锁定跟随字段。默认值和最终 assignment 仍须与当前有效选项及目标格式兼容。
- 工作流输出写入关系改用明确名称，如“同时建立输出组装”，与这里的“绑定选项对照”区分；不能继续用一个“绑定”词指代两种关系。重复组内的对应下拉项具有相同对照取用能力。
- 引用状态明确显示来源分类／字段或表格名及 ID、当前有效项数、只读对照预览，文案为“绑定表格对照 n 项，如有需要可解除绑定”，并按来源补充实际定位信息；其后提供红色“解除对照绑定”。不保留另一份可被误编辑的本地行。
- 点击“解除对照绑定”时，从当前合法有效来源复制一次完整对照及值类型，清除该引用，立即转为 REUSE-02 的可编辑本地状态。后续来源变动不再修改该副本。
- 更新在来源核验保存、活动配置提交后对所有引用方生效，不在浏览器里把未保存表格草稿提前传播到主图／实际测绘。编辑器可在同一候选草稿内展示依赖预览，并明确它尚未应用。
- 按配置提交版本编译并缓存有效对照及依赖索引；公共表保存后使受影响结果失效重算。不得恢复每次渲染重新遍历全部分类／工作流的性能问题。

## REUSE-04：信息卡专用的字段定义绑定

- 信息卡“绑定”中区分“绑定字段设计”和“绑定字段对照／公共表格”。前者控制字段来源路径、名称 zh/en、值类型与格式等字段相关信息，后者控制值对照；工作流不提供整项字段定义的实时绑定。
- 选择“绑定字段设计”时保存字段引用，字段相关输入只读、显示当前有效来源。可默认同时建立该字段的对照引用（该字段有对照时），并将两种引用状态分别显示，允许分别解除。
- 信息卡的显示器选择、分区、排序、可见性、空值隐藏及额外展示布局仍由当前卡片项维护；字段格式变化若与当前显示器无法兼容，核验报告具体使用项，不静默换掉用户的显示器。
- “解除字段绑定”位于“解除对照绑定”之后；只有字段绑定时仅显示“解除字段绑定”。解除时复制当前字段相关有效内容并移除字段引用；另一个独立的对照引用不因解除字段绑定而意外消失，反之亦然。
- 从字段 A 切换绑定为字段 B、或尝试保留另一个不兼容对照表时，预先显示将修改的受控输入并执行一致性核验；不能留下字段值类型与对照不匹配的混合状态。
- 现有信息卡的父子硬继承规则优先：继承项的字段／名称／对照按上游配置和引用一起继承；在禁止本级覆盖时，不能用“预填／绑定／解除”绕开锁定。本级合法的显示器和布局编辑继续保留。
- 引用仅影响配置及显示取用，不因改字段定义而擅自改写数据仓库中的既有要素记录。

## REUSE-05：失效阻断、双语回退及依赖打包

- 绑定目标分类／字段／表格不存在、必需对照为空、循环或不可解析引用、重复／非法存储值、与工作流控件和目标字段的类型／值域不兼容，均产生带分类／工作流／页面／控件定位的阻断报告。不能静默回退空表、旧快照或另一个同名字段。
- 引用失效时“解除”不能自动导入空值并假称成功。保留修复入口：恢复目标、重新选择绑定，或由用户明确确认转为空白本地状态后自行修复；最终合法之前不能保存／激活。
- 字段名称允许 zh 或 en 至少一个非空；两者都空阻断。对照行显示名称采用同样的至少一种语言要求，校验与编辑器提示同步调整，取消此范围内一律强制 zh 的旧检查。
- 按用户本次说明，中文名称显示按 zh → en → 原字段名／存储值回退；英文显示使用 en，缺失时按原规则显示原字段名／存储值，仍不从 zh 填入 en。仅在显示时回退，不把回退结果写回配置；其他无关双语内容不扩展修改。
- 名称／对照更新无需重新预填即可在绑定方生效。工作流默认值、重复组子字段、编辑回灌、输出类型转换和保存校验共享解析后的选项，不能只更新编辑器中的表。
- 单分类、Class 树、工作流和整包导入导出均跟踪传递依赖：导出公共表以及字段对照引用所需的最小依赖描述；依赖存在且内容一致时复用，缺失或冲突时明确处理，不覆盖不相关分类或公共表，也不产生无目标引用。跨包导入可要求先补齐分类字段，或显式转为本地副本，不能偷偷改变绑定语义。
- 全部直接／传递引用纳入使用方列表、删除保护、表格改名、分类模板复制、Class 树覆盖、历史恢复及独立区域保存的核验；保存是原子操作。
- 旧 `optionsTableId` 迁移为公共表引用并保持实时属性；旧内联 `options`／`valueOptions` 保持本地副本，不擅自变为绑定。统一升级契约、schema、迁移、编译／运行、验证器与各类导出文件，正式生成时递增版本，冻结 r10/r6 原样保留。

## WORKFLOW-01：从现有工作流复制模板新建

- “新建”支持空白和“使用已有工作流模板”。模板可搜索并显示名称、ID、模式和适用分类；选择后只需填写新的合法唯一 ID 和名称即可生成独立草稿，其余配置完整复制，后续继续编辑。
- 复制包含页面、槽位、重复组、绘制和附加绘制、条件、输出分类、assignment／ID 组装、便捷测绘开关及编辑用途等完整状态；来源工作流不发生修改，之后也不与模板隐式同步。
- 槽位名和公式引用在新工作流内保持语义一致；需要唯一化的内部身份及它们之间的引用统一处理，不能只换 ID 后留下跨工作流误指。新 ID 重复阻断创建，不把“新建”变成覆盖原工作流。
- 模板已有的公共表／字段对照绑定保持为相同引用，本地副本保持副本；复制前检查依赖与目标分类可用性，创建及保存均核验，错误报告能定位而不破坏原模板。
- 标准 composed 与受支持的 external 方案都可复制：external 保留已注册方案键及采集／编辑用途，不将其源码复制到配置中；编辑用标准工作流的可转换条件和分类匹配冲突仍须再次核验。
- 沿用工作流设计稿导入／导出入口，支持新引用依赖的往返校验；不依赖先保存再复制，不绕过未保存草稿切换规则。

## TAG-01：将固定标签名选项纳入不可删除的标准表

### 已核实现状

- V1 `featureFormats.ts` 的 `TAG_KEY_OPTIONS` 来自分类标签注册项，加上 `category`／`level`／`status`／`source` 四个兼容项，再追加 `__other__`；这些条目中还包含标签值类型，部分可带值选项。
- V3 `WorkflowAnnotationsInput` 当前按输出分类解析 `tags.*` 有效字段形成标签名列表；值控件也读取该字段类型／选项。两处不能直接只换一个文字列表，否则会丢失现有数值／布尔转换和分类专用项。
- 已有“所属枢纽区”“出行方式”表的 ID 是 `teleport-hubs`／`road-travel-modes`；目前删除逻辑只有引用保护，尚无系统标准表的永久保护标记。不能把“预期不可删除”宣称成当前已实现。

### 目标行为

- 新增“标准标签字段”公共表（稳定 ID `standard-tag-fields`）：每行存储值为标签 key，名称 zh/en 为显示名称；`__other__`／“其他字段”是控件固有入口，始终单独保留，不存入可维护表。
- 将该表与所属枢纽区、出行方式一起标识为系统标准表：普通面板不可删除，标准 ID 不可随意更名，内容可依法编辑并通过影响核验。自定义表仍保留引用保护下的删除能力。
- 使用同一公共表主体和列表编辑器；标签专用的类型、输入格式及可选值来源按受控功能元数据保存（如标签字段用途的功能值类型），不依靠中文名称猜测类型。表格模式应支持这种功能值，不把它塞成用户手写的任意 JSON。
- 从当前 V1 固定项、V3 有效标签字段生成去重迁移清单，保留有依据的兼容项和分类专用定义；同 key 定义不一致须列出冲突，不能沿用“先遍历到哪个就采用哪个”。此处不顺带删除既有数据中的标签。
- 工作流标签输入从标准目录读取固定选项，结合当前分类的合法专用定义解析输入类型／值对照；明确区分“可选标签名称目录”和“某标签自身值的对照表”。选择后写回 `tags.<key>`，不写成表格行对象或表格 ID。
- 保留“其他字段”自由填写路径、标签／扩展默认空行集合、既有复杂对象只读保留和自动组装路径冲突检查。仅改选项来源，不重建独立标签扩展页面。
- 标准表不存在、结构无效或对类型产生冲突时，在相关区域与整包核验阻断；旧包通过明确迁移补齐表格，不运行时悄悄采用硬编码备用表。
