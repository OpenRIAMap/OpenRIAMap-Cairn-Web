# 分类迁移中的铁路采集与兼容读取

正式配置 A（r78/c15，fdf0b20f…）已通过真实工作台创建并发布。本变更只补齐产品代码；既有配置声明继续输出旧分类，维护者通过“按当前分类重设范围”明确切换后才输出 RIL/角色。配置 B 与数据 D 仍须通过正常前端发布。

- 整体采集和完整模式铁路格式使用同一明确的受控目标；历史 ID、格式执行器和铁路算法保持。
- PFB 保存所有部件及孔洞，返回、重新编辑、JSON 往返均保留。STB 继续限制一个部件；非法导入明确拒绝，不裁剪。
- 共享线路/站台索引按完整角色范围建立，独立于导航参与范围和图层按钮显隐；配色不再假定 PLF 为 Class。
- 新旧树并存期间，搜索、颜色和卡片读取采用显式对照的只读兼容，不修改原记录、渲染分类或输出准入。清理旧树前必须通过工作台调整实际搜索/关联范围。
- 外部目标缺失、重复、几何不符时显示具体错误，不挂载一个无法正确输出的组件。

## 验证

`test:classification-capture` 覆盖旧/新声明、错误目标、完整几何、严格 STB 负例、隐藏线路关联色和搜索世界/范围限制。保留原 compiled-runtime 性能门槛；对无关分类先排除，避免重复读取。

`classification_capture_acceptance.py` 使用不可变的实际 UI 导出 A 作为隔离夹具，通过生产 MeasuringModule 的实际控件和鼠标绘制完成八项操作：PFB 两部件与孔洞、返回和站台双向/站场输出、原生重新编辑、实际 JSON 下载与导入、非法 STB 导入拒绝、STB 到 PFB 几何导入、铁路输出、STF/SBP 完整模式创建。另以真实删除选择、分类替换导入、标准 ZIP 下载验证旧分类删除标记与新分类同 ID 重建同包存在。仅此类可对照既有正式记录、且非分类内容完全相同的迁移保持原始可选空值；普通导入和字段编辑仍执行原空值清理。测试禁止正式上传，生产配置与正式数据不受夹具影响。

共享核验内核没有修改，生成物检查仍应通过；本变更不要求部署 SCF，也不增加契约版本。

新原生分类的图层身份使用已启用几何分类中的标准 ID/Name，不再依赖旧格式登记。JSON 导入使用默认执行器时仍显示原生编辑表单，允许临时挂载与标准分类 CSV；真正无类型草图保持原有阻断。十项浏览器场景同时覆盖直接采集、导入后编辑、实际 CSV 下载与无类型负例。
