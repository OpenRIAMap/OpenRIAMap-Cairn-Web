# 包级候选编辑与全局引擎独立保存

日期：2026-10-20。适用于 Web PR #44 的最终实现。

整包迁移和有语义错误的导入此前借用了要素编辑草稿，锁住其他设计标签，导致工作流或总体规则中的错误无法在对应区域修正。全局引擎编辑也借用了分类草稿，保存位置随是否选择分类而变化。

现在包级候选与区域草稿分别管理。普通编辑中，对照表、全局引擎、分类分别核验、保存或放弃；整包候选中，三个设计标签编辑同一个隔离候选，区域保存只作暂存，最终由顶部统一核验并保存为本地活动配置。

## 普通编辑

| 区域 | 操作与提交范围 |
| --- | --- |
| 对照表管理 | 核验表格／保存表格／放弃表格草稿，保留原有独立事务。 |
| V3.2 全局引擎默认值 | 新增核验引擎／保存引擎／放弃引擎草稿。保存只替换 engine，不取决于当前选中了哪个分类；读取最新活动配置并检查引擎基线，避免覆盖其他模块或并发引擎修改。 |
| 要素分类定义及管理 | 保留读取分类、核验、保存、放弃的操作；分类草稿与表格、引擎草稿分别管理。 |

未保存的区域草稿仍需保存或放弃，才能切换设计标签；不会在切换时丢弃内容或把另一模块的草稿顺带提交。引擎修改恢复原值会自动结束该区域草稿。

普通区域保存通过后更新本地活动配置。正式发布继续使用既有的全局核验、重新登录、服务端预检及确认发布流程。

## 迁移与整包导入

1. 点击“迁移到 r12 草稿”，或通过“导入本地配置”选择 JSON／ZIP。导入仍先做结构和整包核验：结构损坏直接拒绝；可解析的包进入候选，无论当前语义核验是否通过，都不立即替换活动配置。
2. 顶部显示整包候选操作栏。可以进入总体规则、要素设计、工作流设计，读取和修正对应区域。
3. 每个区域核验并保存后，只更新候选。候选中其他模块的语义错误不会阻止暂存已经修好的区域；本区域自身的错误仍阻断区域保存，结构损坏也不能绕过。区域有未保存编辑时，先处理该区域，再切换标签或执行候选总控。
4. 全部修正后点击顶部“核验整包草稿”。这次始终对完整候选进行全量核验，包括跨模块引用及挂载数据冲突；区域核验通过不能替代此步骤。
5. 无阻断项时点击“保存整包草稿”，确认后才原子替换本地活动配置。如果活动基线已被其他编辑更新，拒绝覆盖并保留候选。也可以“放弃整包草稿”，保持原活动配置。
6. 本地保存完成后，继续正常的发布前全局核验与上传流程。候选存在时，发布入口保持锁定，避免拿旧的已保存配置冒充候选进行发布。

候选、区域草稿、当前设计标签和未保存的工作流编辑会话存入既有 IndexedDB 编辑会话。旧版迁移草稿可自动恢复为包级候选，不必清除缓存。暂存不是生效，整包保存也不等于正式发布。
