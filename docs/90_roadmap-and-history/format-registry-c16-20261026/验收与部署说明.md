# c16 升级验收与部署说明

本轮实现《旧清单退役与正式运行配置统一升级蓝图 v1.1》。正式配置仍为 r91 / c15，正式数据保持既有 v22 / 478 条；本轮没有合并、云端部署、配置激活或数据发布。

## 实现范围

- 完整测绘复用原生编辑计划和核验：四级分类树、手填 ID、新建与修改元数据、未分类草稿隔离、模块快照和世界切换保护。快捷工作流继续使用平铺分类选项。
- 三个专用采集、交易点专用编辑及两个合并工具接入公共原生提交层。保留专用算法和交互；PFB 的完整部件与孔洞保留，STB 单部件约束不放宽。
- c16 明确 roleBindings 与 referenceBindings，工作台可编辑角色分类组、引用来源及搜索参数。c15→c16 移除 coveredClassifications 和旧 target 副本；c13 起各类包逐级迁移、原件和报告保留。
- 桌面／移动端共用配置卡片解析；交易点候选和内链使用当前 NGF／ADM 范围；分享和图层身份读取原生分类。
- 旧全局清单、旧编辑 Schema 被移到历史比较区。冻结 V1 和历史迁移数据保留。生产入口依赖守卫防止间接重新引入旧权威定义。
- Web 与 Pipeline 同步纯 Node 核验器 `cairnmap-c16-production-1`；兼容受支持旧契约和旧任务上下文。不增加启动 SCF 请求，不把全套回归塞入生产 build。

## 已执行验证

1. Web 完整自动化回归 `npm run verify:ci`、TypeScript 和生产构建；新增 c16 角色／引用／迁移／原生提交回归。生产模块图 2,200 个依赖，没有旧清单、旧分类元数据、旧编辑／渲染／搜索表的可达导入。
2. Pipeline 210 项测试在 Node20 和 Node24 执行；c16 归档／发布状态机、任意新分类、错误角色、循环引用、旧上下文和未知契约保护。四个 SCF ZIP 内核与 Web 字节相同。
3. 实际 UI：旧清单中不存在的四级新分类，点／线／面绘制，手填 ID，默认 0，新建、再次编辑、完整 JSON 下载再导入；对比真实输出和元数据。
4. 实际 UI：铁路、车站、STF/SBP、PFB 两部件及内洞、STB 限制、方向／返回、JSON／CSV／标准包、分类迁移删除标记和未分类草稿隔离。新 NGF／ADM／PTA 分类无旧注册项仍可采集编辑。
5. 实际 UI：多点合一同时输出两个站台与一个站场；多面合一输出轮廓与建筑。交易点嵌套列表、合法 0、原生分类、关联检索排除错误分类／其他世界，再次编辑保留创建信息与交易列表。
6. 实际 UI：普通／专用卡的桌面和移动窗口、当前 NGF 地理单元内链、配置来源；工作台缓存、历史组件导入、迁移提示、临时包、模板新建、Class 树、递归删除和编辑范围核验。

浏览器使用独立 localhost Edge 配置和测试数据。没有用测试记录登录或调用正式上传／审核／发布；真实 OAuth、Vercel 和 SCF 上线联调属于下述部署验收。

## 性能结果与已知限制

本次固定 main 提交为 Web `d08c942d62d59653b1f6df94b34b4cfea3517457`，另建原样工作树，在同机同版本浏览器用相同密集场景对比。本轮没有显示新的显著性能退化；数字是本机样本，不能当作所有设备保证。

## 部署与正式验收顺序

1. 审查 Pipeline 和 Web PR，先合并／部署 Pipeline 的兼容核验器。更新提供的 dispatcher、pipeline worker、github mirror worker、review archive worker 四个 ZIP，处理程序保持各自原 handler；运行时保持 Nodejs20.19、原环境变量／权限／触发器，不新增秘密配置。部署完成核对 rulesVersion 为 `cairnmap-c16-production-1`。
2. 合并 Web PR，等待 Vercel 完成。确认正常地图启动免 SCF；此时正式配置仍可能显示 r91/c15，工作台显示“迁移到 c16 草稿”是正确的。代码支持版本和正式配置契约是两件事。
3. 先保留现有本机编辑内容。若正式基线仍是上述 r91，可在工作台明确迁移到 c16，或“导入本地配置”读取本次审查 ZIP。若正式基线已有更新，使用最新正式配置执行工作台迁移，不能强行覆盖为本次旧候选。
4. 查看 17 项迁移提示及角色／引用范围。完成区域编辑保存后，做整体核验，观察验证器和当前挂载数据。警告仍需检查，错误不得跳过。核对三个专用入口、两个合并工具、普通与移动卡、导航和搜索，再使用正式打包下载／上传入口。
5. 通过现有重新登录、候选预检、确认上传／发布流程发布。新的 rN 由服务端确定；等待状态 complete 及 Web 自动部署完成，刷新比较正式身份与 SHA。地图普通启动不应发起 SCF 一致性核验；审核／上传入口仍应核验并在不一致时阻断。

本轮提供离线包和说明，没有代替上述线上发布。c16 激活前可退回配套旧版本；已有 c16 配置或在途 c16 核验任务后，应继续保留 c16 解析能力。需要回退业务内容时，用备份内容迁移为 c16 新候选并走正常发布，不能单独安装不理解 c16 的旧 Web／SCF。
