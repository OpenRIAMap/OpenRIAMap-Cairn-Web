## 3. 保持语义的实施处理

旧 r6/r7 工厂 TPP/WRP 使用高度输入后再由绘制捕获覆盖，是旧绘制表示的一部分。检查器在副本上调用已有的 r8 绘制迁移，再分析写入关系；没有修改原文件、求值器或放松当前配置的重复写入检查。r11 默认流程没有重复目标写入。

ID 组装会改变运行中的 `ID` / 当前 `ID_N`。两个 ID 写入不能只用这些会变化的 token 来证明互斥；检查器对此采用保守阻断。分析预算为最多 128 个条件分支、2048 个条件节点/成员值及每个重复目标 2048 次配对；超限给出诊断，成员集合求交使用 Set 避免二次方扫描。

分类模板复制时，新字段、新信息卡条目以及指向本分类的字段/对照绑定一并重映射；指向其他分类的明确外部绑定保留。新建分类不再通过全包正规化静默删除来源包的对照冲突。布尔控件残留数值/文字规范化属于冲突；需要数值结果时可以在受控组装表达式中显式转换。

颜色检查保留当前使用的 CSS sRGB 形式；依赖外部样式环境的 `var()` / `currentColor` 及尚未接入的设备色彩空间不作为可移植固定颜色放行。按值设色原有六位十六进制约束保留。

## 5. 历史与规模

历史旧审计在 25 份完整包上用时约 6.02 秒，每次都核验/编译。现在列表读取摘要，25 条首屏约 **2–3 毫秒**；100 份历史的首屏约 2–3 毫秒，4 页可完整遍历。具体分段耗时以 [browser-repair-results.json](runtime-v32-release-repair-20261017/browser-repair-results.json) 为准。

列表阶段完整包核验/编译次数均为 **0**；独立按需加载 API 只核验/编译所选包各一次。UI 将该包保存为活动版本时仍执行事务保护，可以再次核验同一包，不会重新加载全部历史。25 份旧历史分 4 批补建；未知 r999 记录保留且拒绝启用。并发写入只有一方能提交，失败方不改变 latest、活动选择或摘要。

95/195/495 节点样本继续合法并可归档重读。495 节点紧凑 JSON 约 11.36 MB；当前仍是单包结构检查与编译，未宣称大型配置完全不会占用主线程。

导入策略集中在 `archivePolicy.ts`：文件/压缩包 64 MiB、累计解压 128 MiB、单条目 64 MiB、512 个条目、JSON 深度 64。ZIP64/多卷明确不支持；未声明附加文件拒绝，目录条目允许但不参与设置。导出也检查可重新导入的体积预算。纯 JSON 没有 ZIP 完整性凭证，仍执行结构与语义检查。

## 6. 应用演练与实际限制

实际 App 使用冻结的正式 COS v19 **495 条真实记录**，验证数据内容、图层按钮、共享 Zoom、普通 WRP 指针绘制保存、临时挂载开关、搜索池、信息卡及刷新恢复；窄屏 390px 无文档横向溢出。正式数据通过隔离 CDP 重放原始响应，未更改应用接口、配置或要素记录，因此不把该演练当作实时后端/CORS 可用性证明。

审核身份门禁保留。真实身份登录、后端审核保存、发布和生产网络故障切换没有进行，本轮没有远程写入。正式替换部署前仍应在目标环境检查这些外部链路。

Worker、大包按 Class 分片、完整已有数据影响审计及双版本可视化比较继续按蓝图列为后续项。本轮不增加上述功能，不以这些后续项替代已完成的阻断修复。

## 8. 简略人工验收

1. 进入配置工作台，在道路工作流中将 `Level` 表达式改成 `"bad"`，核验及保存应阻断；改回原数值槽位后通过，放弃草稿不会修改活动版本。
2. 查看本地历史并翻页；选中版本后才加载。未知或无效版本应显示原因，并可下载原文；恢复默认不会删历史。
3. 导入旧配置和初始 ZIP，再恢复默认；导入失败/取消时原配置保持。r9 FLR/STF 独立文件按提示先经旧整包升级后重新导出。
4. 在实验室核对 RLE、普通点采集和 TPP 绘制回退；确认采集及编辑用流程入口保持原样。

本地正式构建预览：`http://127.0.0.1:5199/?workspace=config-studio&configMode=v3`；实验室把 `workspace` 改为 `config-lab`。应用默认配置仍自动装入 r11/r7，无须重新上传。
