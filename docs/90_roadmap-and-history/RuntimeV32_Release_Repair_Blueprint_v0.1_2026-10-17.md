## 1. 目标、基线与范围

本轮拟解决已经实测的发布阻断和配置管理隐患，使模块核验、总包核验、导出及启用对确定的错误采用一致判定，同时保留现有合法配置、执行结果和历史兼容。

固定产品基线为 `955030f`；审计归档提交为 `754f111`。默认包仍为 `r11-r7.config.json`，`contractRevision=11`、用户包 `revision=7`，SHA-256：

```text
982e1c0b6dc004dd90ee1ff92cd502dfb0f77a9ef4c53bb5a707a2c188460d7e
```

以下要求贯穿全部修复：

- 保持当前已通过的 V1 覆盖，以及已批准的 RLE 小线路标、通用主/附属结构、旧兼容字段清理和绘制状态机制。
- 默认包没有因本轮核验发现确定的内容错误，不为迎合新检查而修改其数据；也不修改冻结的 V1 或历史包样本消除测试失败。
- 不改变合法表达式的求值方式、渲染规则的顺序覆盖、普通预填的独立副本语义、实时绑定和解除绑定行为。
- 不增加重复的业务设置入口。新增诊断、历史分页等界面沿用当前编辑器风格及帮助结构。
- 无效文件可以保留原文并进入安全的诊断/修复流程，但不能因此被保存为活动配置或启用；不能用“拒绝启用”代替“保留文件供检查”。
- 以不改变配置文件契约的修复为优先。确有新的持久字段需求时，先补充契约与迁移设计；本蓝图不预先把用户包强制升级为 r12。

## 3. BASE-01：统一核验边界

### 3.1 检查结果共用

沿用现有错误/警告报告，统一输出稳定的错误代码、配置路径、涉及的节点/字段/工作流/组装行和修复提示。结构检查在语义检查前完成，格式损坏应得到诊断，避免未捕获异常中断编辑页面。

确定影响当前模块的错误，应在该模块核验时显示；保存到活动包、导出和启用时再检查完整候选包，包含跨模块依赖。公共表与分类本就使用整包边界，继续保留；工作流模块不因增强核验而变成可以忽略整包冲突的独立入口。

Class 树内部的“保存”仍只写暂存树，外层保存才注入总配置。暂存树可以保留待处理的跨节点问题，但必须显示未通过状态，不能把它表述为已成功保存到活动包。

### 3.2 审计用例转为回归门

保留原 71 项审计结果作为历史。另建修复后的回归结果，将 9 项已确认漏检改为必须阻断的断言；不能覆盖旧报告，使其看起来从未失败。

审计取证脚本正常退出不代表发布通过。新增正式回归命令在确定应阻断却放行、合法样本被误拒或检查入口结果不一致时，必须返回失败状态。

**验收：** 任一已确认错误不能通过旧“核验通过”报告、单模块保存、直接导出或启用入口绕过；失败操作不修改活动配置。

## 4. P1：发布前关键阻断

### VAL-01：重复目标组装

在每个工作流输出内，按**完整目标路径**建立写入索引，报告相关组装行，而非只检查行 ID 和槽位是否重复。

1. 同一目标存在两个无条件写入时阻断，即使两者值类型相同也不能放行。
2. 同一目标的多个条件写入，仅在条件可以证明互斥时允许；可证明同时成立或其中存在无条件覆盖时阻断。
3. 对暂时无法证明互斥的同目标写入，采用保守阻断，并引导作者合并为一条条件表达式。本初始方案不新增“忽略冲突”或“允许覆盖”的开关。
4. 互斥分析首先覆盖现有受控条件中的 empty/present、equals、in 及 all/any 组合，设置计算预算；超出预算须报告无法判定，不能卡住页面或假定互斥。
5. 不把不同输出中的同名字段误判为重复；不把 `TGTcoordinate` 和 `TGTcoordinate.x` 简单等同于同一完整路径。父子路径写入另行显示覆盖风险，并在默认流程清点中确认其实际组装意图。
6. 清点 assignment、绘制绑定等写入位置。对同一字段存在不同写入入口的情况，也要检查确定的冲突；系统自动几何序列化须与用户组装区分，避免把合法绘制流程误报为用户重复赋值。

如现有已批准流程确实需要有意覆盖，先列出具体流程、顺序及兼容证据，作为蓝图增量明确处理，不擅自改默认包或放松全部重复检查。

**验收：** WF18 在工作流核验、整包、导出和启用四个边界均被拦截；不同输出、互斥条件等合法正例通过，既有 TPP 条件绘制和输出记录保持一致。

### VAL-02：表达式结果类型

基于现有受控表达式 AST 增加类型分析，不执行任意代码，不改变现有求值器。

- 从控件、搜索返回字段、系统 token、绘制返回格式和组装目标字段取得类型与值数量。
- 识别常量、已知函数及条件分支的返回类型，包括文本、数值、布尔、JSON/对象、数组和空值/省略值；输出依赖按现有依赖顺序分析。
- 明确不兼容时阻断，例如文本常量或 `join` 结果写入 number 字段、单值写入多值字段、枚举确定值不在目标对照中。
- 空字符串、空值省略、可规范化的数值输入沿用当前语义，避免把所有可选空值或数值控件的 `"12"` 误判为冲突。
- 无法静态确定的动态结果显示具体警告，并允许在现有试运行/测试能力中提供样例输入核对。不能仅凭有限样例就宣称该表达式对全部输入有效，也不把所有动态表达式一律禁止。
- 创建采集和编辑用途采用同一基础检查；不能依赖“开启编辑用工作流”后才间接发现类型错误。
- 保留提交前实际记录的类型、几何和分类检查，作为运行时保护。

**验收：** WF19、WF20 均在编辑阶段阻断；34 个普通采集记录、外部方案及现有表达式正例保持原结果。增加分支类型、0/false、空值、数组及搜索返回类型的正反例。

### ID-01：稳定标识唯一性

- 同一有效字段作用域内，两个不同字段不能使用相同 fieldId。继承同一字段的合法引用可以复用其身份，不能误判为两个字段。
- 同一信息卡的本地条目 ID 必须唯一，合成继承信息卡后也不能出现有歧义的条目身份；不同信息卡中的同名本地 ID 不直接视为冲突。
- 错误报告同时列出重复 ID、各自 key/条目和来源分类，便于定位。
- 新建、复制模板、分文件导入均使用相同约束。需要生成新 ID 的复制操作，必须一次性重映射相关引用，再核验候选配置。
- 不静默修改已经保存的用户 ID。对于存在歧义的导入文件，保留原文和诊断，不能猜测引用应该指向哪一个字段后直接启用。

**验收：** FD05 和 CD03 均阻断；不会再把选中的 `AuditValue` 绑定成 `Name`，也不会因编辑一个卡片条目同时修改另一个。继承、模板复制、解除绑定及 28 个工作流文件回归通过。

## 5. P2：补齐配置与数据检查

### VAL-03：颜色与动态优先级

颜色检查使用浏览器与离线核验共同采用的解析规则，不能只检查字符串非空，也不能让 Node 环境依赖浏览器专属 API。先盘点现有合法颜色形式，保留已支持的十六进制、RGB/HSL、命名色和透明色；其他 CSS 形式按实际宿主能力明确支持范围。

几何动态优先级与 Label 碰撞指标共用字段能力检查：字段应存在，值数量适合当前计算，并具有明确数值能力；不存在的 `MissingWeight` 不能静默参与计算。数值枚举和继承字段增加正例，不能只允许本地 number 字段。

**验收：** RD12、RD13 阻断；全部默认颜色、字段颜色、既有指标与渲染结果保持通过。

### TREE-01：分类树一致性

以连续的分类 path 定义实际父子关系，核对 children 的指向、重复、遗漏及父级匹配，避免两套分类树逐渐分歧。新建/复制/导入时在候选配置中维护一致性，保留合法的既有排列顺序。

单分类文件可以按现有格式不携带下级；检查应针对**导入合并后的完整候选包**，不能因为文件内 children 为空就拒绝合法的单分类导入。

**验收：** CT04、CT05 阻断；95 个原节点、正常新建分类、单分类、16 棵 Class 树往返通过，不改变 Class 树外层替换覆盖及原子保存方式。

### DATA-01：已有数据嵌套读取

已有数据必填和条件读取统一使用安全的路径读取能力，支持真实的 `tags.*` / `extensions.*` 嵌套结构，修复有值误报和条件漏命中。

保持当前“显式开启已有数据检查”的策略。不要通过本次修复，把全部旧记录自动套用最新字段类型并立即阻断正常使用。

**验收：** 存在的 `tags.nomenclator` 不再误报；满足 `tags.flag` 条件且缺少目标值时正确报告；0、false、空文本、空数组及不同分类范围分别核对。

“完整已有数据影响审计”列为后续增强：可主动检查类型、值数量、枚举和关系，按记录 ID 汇总影响，先给报告，不自动改数据。该增强不作为当前必填标记的隐式新含义。

## 6. IMPORT-01 与 COMPAT-01：导入和版本延续

### 6.1 旧分类文件导入

对单分类与 Class 树建立明确的文件版本识别和迁移过程，先迁移到当前语义，再合并到主包草稿。重点处理 r9 FLR/STF 的旧 visibility/context 与当前结构角色设置之间的转换。

能够无损迁移时，保留字段、显示规则、信息卡及依赖，产生迁移说明；缺少上下文不能可靠转换时，清楚提示所缺依赖和“先导入旧整包、升级后重新导出”的可行步骤。不得把一般性“修正上游冲突”当成所有旧语义转换的替代品。

导入失败不覆盖当前有效包；未知更高契约不得作为当前契约静默解析。单分类父级存在性、固定继承优先、ID 冲突处理及 Class 树暂存/外层注入机制保持。

**验收：** r9 FLR/STF 有可核对的迁移成功结果，或准确且可完成的升级引导；r8–r11 整包、28 个当前工作流和 16 棵升级后 Class 树继续通过，不丢失原文件。

### 6.2 初始 r11 长期兼容

- 保存当前 r11 JSON、ZIP、schema、SHA 和 V1 对照结果作为初始冻结样本，保留 r8/r9/r10 历史样本。
- 区分“旧包可读取并诊断”与“旧包合法、可启用”：新增检查发现旧用户包内已有错误时，应允许保留并定位修复，不能丢弃原内容，也不能为了兼容而放行错误活动包。
- 新契约采用显式迁移链；不得用最新默认配置重建用户旧文件来替代迁移。
- 每次更新同时检查整包、分类、分类树、工作流、对照依赖、迁移后导出重读及关键执行结果。迁移在副本上进行，检查幂等性和原文件 SHA 不变。
- 当前代码不能证明尚未存在的未来版本一定兼容；将这些要求设为未来每次升级的强制回归门。

## 7. HISTORY-01：历史摘要与按需加载

将历史列表与完整配置读取分开。列表只获取分页摘要：包 ID、revision、现有名称/项目身份、时间、内容摘要及核验状态；选中某一版本后，才读取、核验和编译该完整包。

### 7.1 存储与旧数据

- 使用专门的摘要存储及包 ID/revision 索引，避免列表遍历并编译所有历史。
- 完整历史、摘要、latest 和活动选择在同一保存事务中更新，保留同包同 revision 不同内容不可覆盖的约束。
- 首次遇到旧仓库时，分批补建摘要；优先让当前活动配置可用，不用一次完整核验全部历史阻塞首屏。
- 摘要中的旧“通过”状态不能替代选中启用时的重新核验。无效或未知版本保留原文，显示诊断，不从历史中静默删除。
- 不自动清理用户历史；占用提示和主动归档可以后续扩展。

### 7.2 验收

在独立浏览器复测 1/10/25 个历史版本，并增加受控的更大样本。明确记录摘要读取、选中完整包读取、核验和编译四段耗时。

首要算法要求是：**列表阶段完整包核验/编译调用次数为 0；选择一个版本只加载所选包。** 同一验收环境下，25 条摘要首屏以 1 秒内为性能目标，并检查连续翻页、旧仓库升级、中途失败和并发保存。若未达到，记录瓶颈，不能通过减少样本数宣称优化完成。

## 8. ARCHIVE-01：归档完整性与容量

### 8.1 完整性

- 识别并校验支持的 manifest schema；未知版本报告版本不支持，不能跳过 hash 检查。
- 核对 manifest 与 config 的包 ID、revision、契约版本及已有身份字段。
- 对所有声明文件按**原始字节**检查 SHA 和 byteLength，包含附带报告；诊断报告仍不作为配置合法性的凭证。
- 校验必需条目、重复路径和不合法路径；未声明附加内容不能作为隐式设置参与应用，处理规则须明确。
- 已知旧格式走显式兼容分支；纯 JSON 继续接受结构与语义核验，不伪装成已经带有 ZIP 完整性证明。
- 校验、迁移、保存按顺序进行，任一步失败都保留源文件并保持原活动包。

### 8.2 大小与耗时

集中设置压缩包大小、累计解压大小、条目数及嵌套深度预算，避免无限读取。初始容量值在实施时结合现有默认包、495 节点样本和实际导出样本标定，记录在统一策略中，不写入每个世界，也不将本机测试体积当成永久格式上限。

超限要给出明确的实测大小与限制，并保留调整/离线检查的路径。进度提示、失败退出和取消只影响本次导入，不修改已有配置。

**验收：** 原来可读入的报告篡改、未知 manifest、身份不一致和错误 byteLength 全部得到拒绝或明确版本诊断；合法旧包继续可读。补充缺文件、重复条目、超限和失败后活动包不变的测试。
