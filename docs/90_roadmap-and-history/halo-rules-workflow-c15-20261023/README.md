# c15 Halo、规则级交互与工作流分类组

本轮以 Web main `42fc521ff73e97c7c3fa6c0eeaecd83e0c0777fa`、Pipeline main `3ddd7103974b2079fb8acc8d8313a082262e1e4d` 为基线。正式配置仍是 r13／c14，SHA-256 为 `dec9ae55a65517c5c0dcc28b52f829ab5f3bd481f7af95d8f5cd9a7332a68f8c`。本轮不改正式指针、冻结种子或历史发布文件。

## 变化

1. Halo 独立于原填色和描边。基础形状采用解析空心环带，复杂图标和线面使用遮罩，图片使用矩形 SVG 外环；支持小数、虚线、孔洞、多部件和清理。面可独立开启内侧 Halo，开启后在不透明填色上也显示。
2. 圆形统一 SVG。迁移保留旧实际外观并报告转换，新小数不取整。绘制、占用和命中使用公共尺寸；零尺寸和 pending 资源不留下幽灵点击。
3. `multipartAnchor`／`interaction.triggers` 下放到每条规则；总体设置只保留是否允许多部件。锚点和触发按最终命中规则变化。
4. 工作流一个 output 是一个分类组：多行 self／leafDescendants，联合去重后按一个固定绘制类型过滤。每次运行选择一个分类，只生成该组的一条记录。有合法几何的精确父节点在前端和服务端同样可用。
5. 工作流设计页面、控件、组字段、绘制、返回绑定和组装行默认折叠；新增展开，核验定位展开祖先，无业务 ID 的行身份随显式检查点保存。实际填写流程不折叠。

## 本机核验

- `npm run verify:ci`：全部既有矩阵及 c15 新增测试通过。c13→c14→c15 对 95 个分类、16 棵 Class 树、28 个工作流进行逐一导入／核验，原件不变，组件与整包一致。
- 新增核验覆盖空白／父级／模板分类创建、规则级触发核验和精确父分类采集／标准记录导入／服务端／再编辑、候选失效、共同字段、条件组装、跨输出 ID、结构门禁及缺上下文拒绝。
- Chrome 155 与 Firefox 158 的 Halo 像素、DPR 1／2、虚线、孔洞、多部件、图片小数外环及清理检查通过。
- 在同一机器、视口和 DPR 下预热并交替测量 c14／c15。600 条折线、600 个基础符号、600 个图标、200 个孔洞面、1200 个混合符号达到蓝图的创建及交互 P95 目标。原始样本随测试证据交付；性能值是本机结果，不等于所有设备保证。
- 工作台实际执行文件选择导入、显式迁移、区域核验保存、全量候选、颜色映射预览、图标弹窗、四种图片来源、失败回退、线面点状切换和缓存继续编辑；未登录、上传或写入云端。

迁移候选通过核验，错误为 0。报告保留 18 条道路动态组装结构提示（ConnectL／Blacklist 按实际候选分类逐项提示）；这些值需在真实试运行中确认，提交时仍严格核验。

## 交付和部署

同目录的测试证据及外部交付目录包含候选 ZIP、源身份、迁移／核验报告、SCF 包和校验和。候选 r14／c15 是提议值；正式修订仍由发布服务分配。

1. 先合并 Pipeline 变更，上传新的 worker、dispatcher ZIP，发布版本并绑定现有 staging 别名。保留当前全部环境变量和已生效的激活时间，不重新填写当前时间。archive／mirror 的执行代码没有变化，无需为本功能重部署。
2. 再合并 Web，等待 Vercel 生产部署。构建仅做离线生成物、正式镜像、类型和打包检查；普通地图启动不调用 SCF。
3. 确认工作台仍显示当前正式配置的真实 c14；显式点击“迁移到 c15 草稿”，或导入本轮审查候选 ZIP。先保存或放弃已有区域草稿，不清除用户缓存绕过流程。
4. 检查迁移提示中的圆形半径、面内侧行为、规则级锚点／触发和分类组。完成各区域核验保存、整包核验保存，检查实际预览，再进入登录和正式上传发布。
5. 发布完成及 Web 部署确认后，核对 Web／SCF 身份，测试多部件低／高 Zoom、透明符号、图片失败回退、精确父分类采集和再编辑。

真实登录、云端审核、COS 写入及生产发布需要部署后实际验收；本机通过不代表已在线发布。回滚不得让旧核验器接收仍激活的 c15 配置。
