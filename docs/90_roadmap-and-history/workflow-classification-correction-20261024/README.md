# 工作流分类直选与逐候选核验修正

本次修正保持契约 **c15**。工作台设计端仍以四级分类选框定义分类组；实际填写、试运行和工作流式编辑恢复为一个类型下拉框，直接列出末级“代号（名称）”。Kind、SKind、SKind2 末端以及合法 self 父节点可以并列选择，内部值仍保存完整路径。

同名选项只增加必要的父级提示，重复范围去重且保持原顺序。编辑选项与真实编辑范围求交集；深层切换到浅层时删除失效的低层分类。新建按最终选择生成分类系统值与 ID，编辑仍保留原 ID 供用户明确修改。原控件身份、位置、自定义标题和工作区恢复约定保留。

## 组装核验

共同字段集合只提供提示，不再充当预填／绘制／回填的唯一准入集合。字段建议注明覆盖候选数量；实际写入按各候选自己的字段、数量、枚举、格式、坐标和结构约束判断。不同字段定义可以接受同一合法值，未使用的普通可选字段差异不阻断。

配置预检补齐必填供值覆盖：系统字段（包括 ID）、组装、绘制返回及其子字段、合法默认值、手工标签／扩展等分开处理。可确定的缺失报错；受控条件采用有界符号分析。动态值、可变 ID 条件及超预算情况产生具体警告，实际保存始终验证记录。`coalesce` 接受空数组，不能用其后续回退值伪造“必填非空”的证明。

明确的结构类型冲突仍优先报错，不能因某些属性存在性未知而掩盖它。c15 实际值检查由同一纯函数供前端提交、再编辑、导入和纯 Node 入站复用，涵盖有效 HTTP(S) 链接、真实日期和规范坐标结构。历史契约保留原绑定及记录核验语义。

## 核验身份与配置身份

共享核验规则为 `cairnmap-c15-production-2`，前端、Node 和包内 manifest 必须一致。核验器内容指纹使旧本地核验凭据重新检查。Pipeline 仍接受旧 `cairnmap-c15-production-1` 上下文格式，但实际值使用新核验器检查；未知规则身份仍拒绝。

当前正式配置是 **r14／c15**，内容 SHA-256 为 `2d17beba0a943386405e9b536e6897309ca64d4c232d0c88a2afaab2fbccbce7`。本轮没有改写其字节、身份或激活时间，不要求再次迁移或重新发布该配置。

## 回归与证据

新增单元回归覆盖混合深度、同名消歧、精确父级、所有候选实际输出、绑定兼容性、条件必填、父对象默认值、空数组、格式冲突、回填类型和编辑范围。Pipeline 复用同一压缩夹具，检查合法差异、缺失供值及旧 c15 上下文。

`workflow_classification_acceptance.py` 使用可信鼠标／键盘事件、Leaflet 地图点击、生产 V3 运行器和本机提交／再编辑入口，在 Chrome 与 Firefox 实际执行：

1. 当前水域样本的单一下拉框、填写、面采集和保存；
2. 五个混合深度／精确父级／同名候选各自采集和保存；
3. 同一次填写内由深层换到浅层，检查记录和新建 ID；
4. 选项失效时保留已填草稿，要求主动重选；
5. 唯一候选自动确定；
6. 点／线／面混合分类树固定 Polygon 时，只列面候选并保存规范 CoordG；
7. 编辑范围筛选、非法链接阻断、修正后保存及浅层分类清理。

浏览器夹具会拒绝任何远端、API 或写请求，并记录可信输入事件和本次核验器指纹。本地验收不替代部署后的真实登录、SCF／COS 提交和审核发布验收。

最终本机结果：Web `verify:ci` 与生产构建通过；Pipeline 208 项测试及部署／SCF 包校验通过；Chrome 和 Firefox 各 8 组实际操作通过。既有工作区 7 组和 c15 编辑／迁移／渲染 18 组浏览器回归通过，均无运行时错误或云端写入。构建保留原有的大块体积提示，未放宽检查或性能阈值。

原 c15 迁移测试曾将活动正式指针当作 c14 样本，正式配置发布到 c15 后会失败。本次将迁移／渲染参考固定为摘要校验的不可变 r13／c14 原件；当前正式配置继续由生产构建检查独立核验。同契约核验补丁版本也不再被维护测试固定成 `production-1`。

实现依据见保留的 [蓝图原件](blueprint-v1.0.md)。最终验收 JSON 和截图位于本目录 `evidence/`；完整日志及 SCF ZIP 随本机交付目录提供。

## 部署顺序

1. 先处理完旧核验器下已确认但未结束的配置发布任务；旧确认凭据不自动升级授权。
2. 合并配套 Pipeline PR，上传新 worker／dispatcher 包，保留原环境变量与激活时间，发布新版本并重新绑定原 staging 别名。
3. 合并 Web PR，等待 Vercel 生产部署完成。生产构建仍为离线检查，不访问 SCF。
4. 正常刷新，按原工作区恢复弹窗决定继续旧草稿或恢复当前正式配置；不强制清缓存。
5. 确认工作台仍为 r14／c15，实际采集与编辑界面是单下拉框。先本地采集检查分类和字段，再进行业务入口一致性检查及真实审核链验收。

设计端的分类组与四级范围选择仍然存在。Halo、规则级锚点／交互、设计折叠及铁路／车站外部算法保持既有设计。
