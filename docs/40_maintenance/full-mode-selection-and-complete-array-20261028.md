# 完整模式分类锁定、兼容切换与完整数组实施记录

依据用户批准的《完整模式分类锁定、兼容切换与完整数组升级蓝图 v1.0》。基线为 PR #62 合并提交 `1e5708701a594a9a85767628e3382daa3a54a0d0`。

## 操作变化

1. 已有要素再编辑仅显示当前编辑工作流实际接纳的单下拉框，保留原候选标题与消歧方式；不显示四级树或跨方案切换按钮。唯一候选锁定。改选仍检查当前几何及多部件政策，不删除数据。
2. 完整新建先选四级分类，再点击整行“确认选择并导入”。几何由既有最高优先级编辑路由决定，原点／线／面先选按钮移除。载入后分类锁定。
3. “解锁分类选择”检查已有字段值和草稿几何；缺失必填值及未成形路径可保留。进入切换时保存不可变快照，冻结字段、地图输入、工具、撤销重做和输出。“尝试切换”成功后原子替换；失败保留原快照。“恢复原分类”恢复原输入、焦点及历史。
4. 目标线不限制顶点数量，目标点每部件最多一个坐标。目标必须容许当前部件数；面内洞及空洞槽不能通过换类型丢弃。字段按保存路径及有效输入标准比较，保留非空文本、0、false、JSON／组装值，使用目标绑定回填后再次比对。未填的目标必填项留待输出核验。
5. 原“数组编辑”按钮改称“数组”，弹窗和焦点范围不变，仍可反转当前路径。旁边新增“完整数组”，独立文本事务，无反转；展示全部 CoordP／CoordL／CoordG 层级，严格检查数字三元组、结构、拓扑和分类政策，再交原测绘模块整份应用。
6. 完整数组顺序即部件及内洞编号顺序。有效焦点保留，越界焦点退回有效外环；完整替换可整份撤销重做。桌面／窄屏保持同一文本事务；世界暂停或失效回调不能覆写原草稿。

## 实现边界

- `MeasuringModule` 仍是几何和部件／内洞结构的唯一所有者。未恢复或新增部件／孔环快捷按钮。
- 字段转移位于客户端草稿层；未放宽正式记录核验，未运行正式输出来冒充临时保存，未改写创建信息或自动重建 ID。
- 仅改 Web 客户端、回归脚本与维护说明。配置结构、r93／c17、共享核验内核、渲染器、SCF 及生产数据不变。
- 原生及专用表单仍使用现有路由与明确绑定。已有专用采集、两个合并工具和铁路端点反转保留。

## 验证

- `npm run verify:ci`：完整本地回归通过；最后增加的嵌套数值及组字段原文保留用例另行通过 `npm run test:full-mode-selection-array`。
- `npm run build`：通过 TypeScript、生产构建与冻结 V1 文件检查；存在原有较大 chunk 提示。
- 新增实际控件脚本 `full_mode_selection_array_acceptance.py`：九组场景，覆盖明确载入、切换失败与恢复、跨 Class 不同槽位回填、晚到工具回调拒绝、全部部件与洞重排、整份历史、再编辑范围、世界暂停及 1440／390 布局转换。拦截器确认无外部或写入请求。
- 原单一绘制会话二十组、五项修复六组，以及分类采集、工作流分类、c16 完整模式往返和专用工具浏览器回归均通过。旧脚本只调整经批准已变更的先选类型／分类控件／按钮交互，保留几何、内洞、保存、身份和导入导出断言。
- 两套浏览器生成的记录交由既有 c17 纯 Node 入口核验；覆盖完整数组生成的两部件、第二部件两个洞，并确认洞越界仍被拒绝。新增脚本及 Node 核验已接入 PR CI，未加入生产 build 全量测试链。

浏览器测试使用独立本机沙盒和正式配置副本，其中跨 Class 情境使用本地有效夹具。它们不代表已在生产环境登录、上传或发布。远端检查结果以 PR 最终状态为准。
