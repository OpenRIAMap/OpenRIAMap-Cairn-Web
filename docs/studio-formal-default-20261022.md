# 工作台正式默认、单份缓存与临时诊断包

对应《工作台缓存、临时诊断包与设置精简升级蓝图 v1.0》，统一包含在 Web PR #49。用户设备的清理只会在部署后首次加载新版配置编辑功能时执行；本地验收仅使用独立测试浏览器。

## 正式默认与进入选择

工作台和运行实验室的“恢复当前正式配置”从 Web 静态 `configuration/current.json` 读取当前发布身份，获取受控散列地址的配置，完整核验摘要、语义和身份，并复查正式指针。读取失败保留现有工作稿，不回到冻结 r7 种子，也不请求 SCF。

存在本机检查点时，先显示本机修订号／契约、缓存时间、核验状态及 Web 正式身份。选择“继续编辑”前不激活该稿；选择“恢复默认”在成功取得正式配置后才删除检查点。未选择即退出，不改写检查点。工作台、旧工作流链接、运行实验室共用此入口。

## 单份检查点与退出

- 编辑时合并、防抖、串行覆盖同一检查点，保存三页文档、未保存区域、整包候选、分类和工作流新建表单、选择和展开状态、核验报告。报告恢复不恢复本次正式输出授权。
- 应用内退出遇到未核验、核验失效／失败或未保存区域时，可选择“确认，缓存并退出”或“取消缓存，清除并退出”。关闭弹窗／Esc 留在编辑器。已完整核验但未发布的修改保留单份检查点，下次仍明确选择；纯默认不制造无意义缓存。
- 直接关闭／刷新使用浏览器原生离开提示，提前维护检查点，隐藏时补充写入。强退只能保证已写入的检查点，不能保证最后尚未写入的输入。BFCache 返回也重新询问，原生“取消离开”不清空缓存。
- 检查点使用事务和写入代次；旧窗口拒绝覆盖新窗口。清除先停止后续写入，防止退出钩子复活缓存。缓存失败显示原因、成功时间及重试；临时导出可以明确选择仅下载副本。

## 旧缓存迁移

原数据库 `cairnmap-config-lab-v32` 升级为 v3。单一事务先归并旧未完成编辑会话及基线，其次才保留明确选中的旧本地配置；不选修订号最大的历史版本。归并稿先等待用户选择。

删除旧 `recovery:*`、完整修订历史、历史摘要及 latest／active-choice／session 等旧记录；删除恢复备份面板，停止生成恢复副本。保留独立修订号高水位，导出时仍避免重复分配旧修订号。迁移失败不删除当前工作稿。只处理指定的编辑器记录，不清空整个站点存储，不触及测绘草稿、世界数据、布局、登录、正式已核验缓存或 COS／GitHub 历史。

## 临时诊断包

“临时保存和下载”要求各区域完成保存／暂存，并针对当前内容完成全局核验，允许核验结果有问题。正式下载／上传依旧要求当前完整核验通过；编辑或挂载数据变化使旧结果失效。

临时 ZIP 保持正常 `config.json` 的内容、修订号和可读缩进，增加可选的 `reports/temporary-validation.json`。报告记录实际 JSON 摘要、契约、核验器／资源指纹、检查范围和完整问题；正常 manifest 声明、大小及散列校验继续执行。

通过“导入本地配置”打开临时包时，显示历史报告并隔离编辑语义有误的配置，不激活错误稿。契约、核验器或关联摘要失配时提示确认，随后重新完整核验。历史报告永不直接解锁本次正式输出。结构损坏、未知契约、不安全 ZIP 或归档完整性错误仍阻断。

临时报告不是必需文件，已有正式 ZIP／裸 JSON 保持兼容。修复后正式导出重新组装原有允许文件，保留标准核验报告，不含临时诊断文件。临时报告读取位于独立的前端伴随读取器；共享服务端 `nativeArchive.ts` 与 vendor 核验器没有改变。

## 设置精简

实际来源对比只常驻“比较权威来源和镜像”按钮，点击后比较并在弹窗显示；不增加打开设置自动比较或轮询。数据来源切换仍保留。正式配置身份移到工作台入口下方；删除 Data Tool Schema 设置模块及失去调用者的前端导出器。

## 验收

- `npm run verify:ci`：完整回归通过；包括正式默认、临时包、工作流、导航、搜索、发布与业务门禁。新增完整回归和本机 Chrome 工作区流程加入 PR CI，未加入每次生产部署。
- `npm run build`：类型、正式配置完整性、资源／共享核验器边界、冻结 V1 与生产打包通过；原有大分包提示仍存在。
- Chrome 独立 UI／IndexedDB：真实编辑、退出保留／清除、重开选择、未选择关闭、临时包失败核验→下载→导入→修复→正式输出、表单恢复、旧库清理、高水位、过期写拒绝、配额不足、BFCache 选择通过；另行实际杀浏览器进程，恢复最后成功检查点通过。
- Firefox 158.0.1：应用内退出和 Esc、未激活前选择、390px 窄屏和键盘焦点、未保存输入恢复、原生刷新提示及恢复默认通过。
- 设置实际组件：位置、按需结果弹窗和来源切换保留通过。

浏览器验收阻断外部网络与业务 API；没有真实登录、SCF 发布、云数据写入。Firefox 外部代理阻断加 HTTPS 拦截；Chrome 在页面导航前阻断外部请求。检查点失败注入及 BFCache 事件测试不声称覆盖所有操作系统终止时序。

## 合并后的步骤

1. 合并 PR #49，等待 Vercel 生产部署完成，再刷新 `https://cmap.ria9.top/?workspace=config-studio`。
2. 有旧当前工作稿时，先看到选择弹窗。需要继续工作就选择“继续编辑”；需要当前正式版本就选择“恢复默认”。旧恢复备份浮层应消失，版本来自正式静态索引，不从 r7 种子恢复。
3. 修改一个区域但不保存，测试关闭→缓存→重开→继续；再测试“取消缓存，清除并退出”，重开应回到当前正式配置。
4. 在本地副本制造语义问题，各区域保存后全局核验，正式输出应禁用、临时下载可用；导入下载的临时 ZIP 查看报告，修复后重新核验，正式 ZIP 不再包含临时报告。无需为验收上传任何配置。
5. 确认设置对比按需弹窗、正式身份位置和 Schema 模块移除。

本轮无需 SCF／CAM／CORS／环境变量更新，不提升正式配置契约，不要求重新发布正式配置包。
