# 工作台默认配置读取修复

此前正式主地图使用 `public/configuration/current.json`，工作台的默认值和“恢复应用默认配置”却始终读取冻结的 r7／契约 r11 种子。因此正式配置已发布为契约 r13 后，点击恢复仍会回到 r7／r11，并再次显示迁移按钮。

本轮基于 main `68ec3ef313ee3ea6d703ad9f41e16e2fdb287365`，保留既有正式配置、冻结种子、V1 兼容资源和服务端核验器。

## 新行为

- 按钮改名“恢复当前正式配置”，工作台和运行实验室使用相同逻辑。
- 首次打开或默认选择时读取 Web 静态正式索引，按受控散列地址获取配置，校核 SHA-256、完整配置语义及版本身份，再复查索引。显式恢复每次重新读取，不沿用页内旧默认值。
- 网络、摘要、语义或身份核验失败，以及读取期间正式指针变化时，保留原本地活动配置及选择，显示错误并允许重试。没有退回历史种子的兜底。
- 恢复前保留原本地活动配置的恢复副本，原本地历史不被覆盖。若之后保存正式配置的本地副本时修订号与旧历史冲突，自动分配新修订号。
- 显式选中的本地配置继续保留。未完成的编辑草稿保持原基线，恢复操作在界面与数据层均被阻断；不能借运行实验室绕过其他区域草稿。
- 仅获取 Web 静态资源，不请求 SCF、不执行登录、上传或发布，也不激活或热切换主地图的正式配置状态。

## 核验

`npm run test:studio-formal-default` 覆盖契约 r11／r12／r13、内容摘要、发布身份、受控 URL、语义错误、指针变化、失败后重试及各个草稿区域；已纳入完整 PR CI，未添加到生产构建重复执行。

`npm run test:r12-capabilities` 和 `npm run build` 通过。独立浏览器验收实际工作台恢复按钮、刷新、IndexedDB 副本、网络／摘要失败、本地历史冲突与旧基线草稿保护；使用本机 HTTP 服务，导航前在浏览器网络层阻断外部 HTTPS，包括既有站点统计脚本，无真实登录或云写入。

## 部署后

合并 Web PR，等待 Vercel 生产部署完成，刷新工作台，点击“恢复当前正式配置”。当前正式身份应显示“配置 r11 · 契约 r13”，不再出现迁移到 r13 的按钮。若保留了未完成的草稿，先完成或放弃该草稿。无需 SCF、CAM、环境变量更新或再次发布配置包。
