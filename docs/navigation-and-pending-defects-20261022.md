# 导航坐标与待处理缺陷修复

本轮直接基于 Web main `c22f1e9404d9bfa94831bca92940552655ef612a`，包含刚完成的配置 r11／契约 r13 正式指针。配置文件、冻结 V1、验证内核及导航权重保持原有版本。

## 导航几何与错误提示

铁路线路、站台、站场、车站建筑、站体搜索，以及传送点、Warp 和道路均通过 `navigationGeometry` 接入既有 `readMultipartGeometry`。支持 CoordP/L/G 及该读取器的旧格式兼容，冲突、损坏和不支持的部件结构保留 ID 与原因。铁路界面显示算法返回的原始失败原因，站体搜索准备失败也明确显示。

单部件 STB 的多边形中心计算和范围判定沿用原算法。多部件不取第一部件或拉平后继续导航；没有增加多部件或内洞寻路算法。用户可继续通过配置禁止 STB 多部件。本轮没有替用户修改正式分类配置。

`test:navigation-canonical` 使用只有规范坐标的独立夹具，覆盖契约 r12／r13、三类导航、站体搜索和 CoordG 中心；另测无效几何、新旧冲突、单部件限制和 Warp 目标缺失。原夹具继续覆盖兼容读取。

## DEF-01、BUILD-01、CI-01

预览和胶囊场景改用固定历史样本；正式 current 的验证不依赖固定 nodeId。生产构建使用 `verify:production-build`：检查实际 current 和全部不可变目录，包含尚未激活的新候选，验证身份、支持契约、语义、原始摘要、manifest、ZIP 内容、资源能力、冻结种子和共享内核。随后执行 TypeScript、Vite 和冻结 V1 安装。

完整历史、故障注入、规模和能力回归放在 `verify:ci`，CI 只调用一次，再执行生产构建及既有下游检查。`test:config-v32-acceptance` 仍执行完整回归和构建。

每个历史包仍会接受完整性检查，检查时间会随发布文件数量增加；本轮没有引入可绕过真实字节核验的缓存。

## PUB-01

保留“不可变文件部署 → COS 激活 → Web current 镜像”的发布顺序。服务端返回 complete 后，工作台另外检查最终 Web 静态身份、配置原始 SHA-256，并再次读取 current 防止并行发布期间误判。结果明确区分待部署、已确认、后续版本及读取失败；允许只读重试。

正式基线刷新不再清除正在跟踪的发布任务，旧候选也不能在新基线下继续使用。最终部署检查不访问 SCF，不改变服务端状态、不重新提交配置。两次部署仍然保留，构建提速降低其成本；本轮不合并提交或改变跨存储发布协议。

## SEARCH-01～04

关联搜索在聚焦／输入后准备。世界、来源、传输、读取器、资源组、远端世界与来源代次一致时，复用地图内存数据；否则按完整来源身份合并同一批在途读取，继续执行原摘要和发布一致性检查。

本地图层先覆盖基础记录，再应用搜索范围和删除标记，避免编辑后离开搜索范围的记录仍显示旧候选。普通 bridge 对象重建不再触发加载；实际图层内容、删除标记、配置、世界、来源或数据快照变化仍会更新候选。

等待限制在当前输入区域，显示真实最新阶段与不定进度，可取消、可重试。搜索总等待 30 秒，单对象读取 30 秒，共享数据任务 60 秒。取消只移除当前使用者，最后一个使用者离开才中止底层任务；不取消地图仍在使用的请求。错误与空结果分别显示，退出不改写或丢弃测绘草稿。
